# 사주·AI·개인정보 기술 명세

버전: 1.3 · 2026-11-04 · 상태: 구현 전 제안 명세

**현재 구현 범위는 무료 기본 사주와 이메일 상담 안내다. C 관련 API·AI·호출 제한·비용 통제 설계는 유료 AI 풀이의 후속 참고 명세이며 이번 구현 대상이 아니다.** 초기에는 AI 서버 코드·결제·유료 상품을 만들지 않는다. 소재지는 `서울 강북구 한천로 1167 3층`, 대표 정보·상담 이메일은 공란으로 유지한다.

`기본안`은 구현 선택의 출발점이고, `운영자 확정`은 공개 전 확인해야 할 사업/명리 기준이다. 아래 예시 스키마·설정·숫자는 실제 구현·테스트·계약이 완료되었다는 의미가 아니다.

## 1. 권장 구조와 기술 결정

### 1.1 기본 배포안

**일반 Astro 정적 사이트 + Cloudflare Workers Static Assets + 필요한 경로의 Worker API**를 권장한다. BrawlNote의 정적 콘텐츠 운영 원칙을 계승하되, 신규 프로젝트에 Workers를 권장하는 현재 Astro 공식 안내를 반영한다. Starlight와 Astro SSR 어댑터는 초기 필수가 아니다. [Astro 배포 안내](https://docs.astro.build/guides/deploy/cloudflare/)

```text
방문자
  ├─ 소개·상담·칼럼 → 정적 HTML/CSS/이미지
  ├─ 무료 기본 사주 → 브라우저의 검증된 계산 모듈 + 고정 풀이
  └─ [후속 계획만] 유료 AI 설명 → 동일 출처 POST /api/v1/saju/interpret
                         ├─ 입력·동의·봇·호출 제한 검증
                         ├─ 서버에서 같은 계산 모듈로 재계산
                         ├─ 원자적 예산 예약·중복 처리 방지
                         ├─ 최소 계산 사실만 AI 공급자에 전달
                         └─ 결과 검증 → 브라우저에 반환

운영자 → Markdown/사업정보 수정 → Git 검증 → 미리보기 → 운영 배포
```

- A+B는 개인정보를 저장하는 고객 DB 없이 운영한다. B의 생년월일 계산은 기본적으로 브라우저 안에서 수행한다.
- C에만 Worker API와 원자적 제한 저장소를 추가한다. 저장소에는 호출/비용/중복 상태 등 최소 운영 메타데이터만 둔다.
- C의 브라우저 결과를 서버가 그대로 믿지 않는다. AI 호출 전에 원본 입력을 서버가 검증·재계산하고 허용된 사실을 구성한다.
- 연락처와 개인 사주 결과를 연결하는 고객 DB는 D의 별도 설계 대상이다.
- 초기 상담은 이메일만 제공한다. 상담 이메일 미제공 상태에는 준비 중 안내만 표시하고 접수·발송·예약 기능을 만들지 않는다.
- 최초 환경은 개발·미리보기·운영을 분리한다. 운영 키·고객 데이터·실제 분석 태그를 개발 환경에 공유하지 않는다.

Workers는 정적 파일과 API 경로를 함께 제공할 수 있다. 기본은 정적 파일 우선이며 API 경로에만 Worker 우선 처리를 설정한다. 정확한 적용은 선택한 Wrangler 버전으로 검증한다. [Static Assets](https://developers.cloudflare.com/workers/static-assets/), [설정·바인딩](https://developers.cloudflare.com/workers/static-assets/binding/)

다음은 **구현 시 검증할 설정 골격**이다. 실제 리소스명·호환 날짜·환경별 설정을 채워야 한다.

```jsonc
{
  "name": "hakso-preview",
  "main": "workers/index.ts",
  "compatibility_date": "2026-11-04",
  "assets": {
    "directory": "./dist",
    "binding": "ASSETS",
    "run_worker_first": ["/api", "/api/*"],
    "not_found_handling": "404-page"
  },
  "vars": {
    "AI_ENABLED": "false"
  }
}
```

A+B만 구현할 때 Worker 코드가 불필요하면 정적 자산 배포로 시작해도 된다. C가 추가될 때 위 엔트리와 API를 연결한다. SPA의 모든 주소를 200으로 돌려주는 설정은 적용하지 않는다. Worker를 통과하지 않는 정적 응답에도 필요한 보안 헤더가 적용되는지 실제 HTTP로 확인한다.

Cloudflare Pages를 이미 선택한 사유가 생기면 **Astro 정적 출력 + 별도 Worker API**를 대안으로 검토하고 결정 기록을 남긴다. Pages와 Workers 두 운영 파이프라인을 동시에 만들지 않는다. 기존 BrawlNote 배포 설정을 복사해 새 리소스에 연결하지 않는다.

### 1.2 개발 도구

| 항목 | 기본 제안 | 구현 시 확정할 것 |
| --- | --- | --- |
| 프런트 | Astro + TypeScript + 일반 CSS | 지원되는 안정 버전, 브라우저 범위 |
| 콘텐츠 | Astro Content Collections + Markdown | 선택 버전에 맞는 API, 승인/초안 스키마 |
| 클라이언트 사주 | 지연 로드하는 독립 TS 모듈 | 라이브러리·라이선스·시간대·기준 사례 |
| 서버 | Cloudflare Worker | 런타임 호환, 로컬·원격 동작 |
| 제한/예산 | C 단계의 Durable Object 등 원자적 저장소 | 요금·정합성·TTL·동시성 테스트 |
| 단위·계약 테스트 | Node test runner 또는 Vitest 중 하나 | ESM/TS 구성과 유지비를 보고 하나로 통일 |
| 브라우저 테스트 | Playwright | Chromium + WebKit; 실제 Safari 별도 |
| 패키지 | npm + lockfile | `.nvmrc`, `engines`, `packageManager` 고정 |
| 저장소 | **BrawlNote/hakso / Private** | `https://github.com/BrawlNote/hakso.git`; 생성·Edge 접근 확인, 배포 별도 |

Node는 착수 당시 선택한 Astro·Wrangler를 지원하는 LTS를 확인한 뒤 정확한 버전을 기록한다. BrawlNote 로컬의 버전 숫자를 무조건 복제하지 않는다. `latest` 설치는 최초 선택에만 제한하고 이후 `npm ci`로 재현한다. Python은 학소 프로젝트의 필수 의존성이 아니다.

### 1.3 디렉터리 제안

다음 구조는 후속 C까지 포함한 후보 구조다. `workers/api/interpret.ts`, `workers/ai/`, `workers/quota/` 등 AI 관련 파일·리소스는 초기 A+B에서 만들지 않는다.

```text
hakso/
  README.md, ANTIGRAVITY_WORK_ORDER.md
  .nvmrc, .gitignore, .env.example, package.json, package-lock.json
  astro.config.mjs, wrangler.jsonc
  src/
    layouts/SiteLayout.astro
    components/       # Header, Footer, CTA, SajuForm, SajuResult 등
    pages/            # 요구사항의 공개 URL
    content/articles/, content/notices/
    content.config.ts
    data/business.ts, consultation.ts, faq.ts
    styles/tokens.css, global.css
    lib/saju/         # 입력 정규화·계산·정책·고정 해석; 서버와 공유
    lib/analytics/    # 허용 이벤트만
  workers/
    index.ts
    api/interpret.ts, health.ts
    ai/provider.ts, prompt.ts, output-schema.ts
    security/, quota/
  public/             # 검수한 이미지·공유이미지·robots 등 공개 파일만
  tests/unit/, contracts/, e2e/, fixtures/
  scripts/            # 콘텐츠·링크·공개 자산 검증
  docs/               # 본 기획·결정·시험·운영 인계
```

`business.ts`에는 사업 정보만 둔다. AI 비밀 키를 넣지 않는다. 개인정보 관련 내부 증빙·미공개 후기 원문·계약서는 `public/`, `src/content/`, 공개 저장소 어디에도 넣지 않는다.

사업 정보 스키마에는 확인된 소재지와 `consultationMode: 'email'`을 반영한다. `representativeName`과 `consultationEmail`은 빈 문자열 또는 명시적 미입력 값으로 두고, 화면에서 해당 빈 항목을 숨긴다. 값이 없을 때 `mailto:`를 생성하지 않는다. 확인되지 않은 전화번호·이메일·이름을 기본값으로 넣지 않는다. 이 스키마 설명은 구현 코드 생성이 아니라 개발 시 적용할 계약이다.

## 2. 만세력 계산과 풀이의 책임 구분

시스템은 세 계층으로 나눈다.

1. **역법·시간 처리**: 날짜 유효성, 양음력 변환, 윤달, 시간대, 절입 시각.
2. **학소 계산 정책**: 연주·월주·일주·시주 경계, 보정, 지원 범위, 시간 미상 처리.
3. **해석**: 학소가 검수한 고정 풀이와 선택적 AI 설명.

AI에게 생년월일을 주고 간지·음력 변환·절기·대운을 추측하게 하지 않는다. 역법 일치와 명리 해석의 타당성은 다른 문제다. 계산 테스트 통과를 미래 예측의 정확도나 과학적 검증으로 광고하지 않는다.

한국천문연구원 음양력 API는 달력 변환·윤달 등의 대조 자료로 활용할 수 있다. **해당 API의 음력 월 간지를 사주의 절기 기준 월주로 그대로 대입하지 않는다.** 달력 정보 API는 학소의 명리 계산 정책이나 해석을 검증해주는 완성 사주 엔진이 아니다. [공공데이터포털 음양력 정보](https://www.data.go.kr/data/15012679/openapi.do), [한국천문연구원 천문 정보](https://astro.kasi.re.kr/)

### 2.1 엔진 선정 과제

| 평가 항목 | 통과 조건 |
| --- | --- |
| 권리 | 상업적 이용·재배포·수정 조건 확인, 출처/고지 의무 기록 |
| 한국 역법 | 한국 음양력·윤달 대조; 중국 음력과의 차이를 무시하지 않음 |
| 절기 | 월주에 필요한 절입 순간의 기준·정밀도·시간대가 설명됨 |
| 실행 환경 | 브라우저와 Workers에서 같은 입력으로 같은 계산; Node 전용 기능 의존 점검 |
| 지원 범위 | 지원 연도·시간대·미상 처리 범위를 명확히 반환 |
| 검증 가능성 | 독립 출처 기대값을 가진 사례로 비교; 함수 자체의 값을 정답으로 재사용하지 않음 |
| 유지보수 | 버전 고정, 업데이트 이력·의존성·보안·공급 중단 대안 기록 |
| 크기·성능 | 체험 페이지에서만 지연 로드; 저성능 모바일에서 측정 |

실무자는 후보를 2~3개 조사하고 작은 비교 실험을 한 뒤 결정한다. 한국 역법과 정책을 검증할 수 없는 라이브러리는 이름이 유명해도 채택하지 않는다. 필요하면 상용 만세력 API도 후보가 될 수 있으나, 상업 사용권·응답 계약·비용·외부 전송·장애 의존성을 함께 비교한다. 무단 크롤링으로 타 사주 서비스의 결과를 수집하지 않는다.

### 2.2 공개 전 확정해야 할 계산 정책

| 정책 항목 | 제안/검토 기준 | 미확정 시 처리 |
| --- | --- | --- |
| 지원 출생 범위 | 엔진·역법·시간대 검증 범위의 교집합; 미래 출생일은 거부 | 공개 입력 범위를 정하지 않음 |
| 출생 지역 | 1차는 대한민국 출생으로 제한하는 안 | 해외 출생은 임의 KST 계산하지 않고 미지원 안내 |
| 시간대 | IANA `Asia/Seoul`, 출생 당시의 오프셋 적용 검토 | 과거 표준시/DST 미검증 구간은 제외 |
| 연주 경계 | 입춘 절입 순간 기준을 기본 제안 | 운영자 확정 전 기준 결과 공개 금지 |
| 월주 경계 | 월주용 절(節)의 절입 순간 기준 제안 | 음력 초하루로 대체하지 않음 |
| 일주 경계 | 00:00 기준 제안; 야자시 분리 여부 운영자 결정 | 23시대 포함 경계 검수 전 배포 금지 |
| 시주 | 운영자가 채택한 시진과 일간 연동 규칙 | 임의 표 사용 금지 |
| 태양시·경도 보정 | 초기 미적용 제안; 그 사실을 계산 안내에 표시 | 자동으로 숨겨 적용하지 않음 |
| 시간 미상 | 시주 `null`, 관련 해석 생략 | 임의 12:00 입력 금지 |
| 대운/세운·용신 | 최초 자동 풀이 제외 제안 | 확정 계산 규칙 없이 표시 금지 |
| 해석 기준 | 학소 검수 원고와 규칙 버전 | 임의 AI 학파 혼합 금지 |

법정 시각과 태양시 보정은 별도 개념이다. `UTC+9`를 모든 한국 과거 출생에 고정하면 안 된다. 서머타임 전환으로 존재하지 않거나 두 번 존재하는 현지 시각은 모호성을 해결하거나 미지원으로 처리한다. 실행 중인 맥·서버·브라우저의 현재 시간대로 출생 시각을 바꾸지 않는다.

절입 직전/정각/직후, 23:00/00:00 경계는 정책과 분·초 정밀도에 따라 결과가 달라질 수 있다. 사용자가 분 단위로만 알고 있고 경계와 겹치면 확정된 단일 결과처럼 보이지 않게 한다. 입력 정밀도 내에서 결과가 달라지는 경계는 “추가 확인 필요”로 계산을 중단하거나 정책에 맞는 후보와 차이를 설명한다.

정책은 `calculationPolicyVersion`으로 식별한다. 정책 변경 시 기존 사례를 재검증하고 표시 문구·풀이·문서도 함께 갱신한다. 기준 차이가 발생하면 무조건 라이브러리 버그로 판단하지 말고 역법·학파·시간 정책 중 원인을 기록한다.

날짜만 있는 입력은 연·월·일 값으로 파싱한다. `new Date('YYYY-MM-DD')`의 UTC 해석이나 기기의 기본 시간대에 기대어 생일을 하루 이동시키지 않는다. 음력 입력을 양력으로 정규화한 뒤 출생지의 당시 현지 시각과 결합하는 순서를 명시하고, 브라우저/Worker 모두 같은 정규화 계약을 사용한다.

## 3. 사주 체험 입력·출력 계약

### 3.1 최초 입력

| 필드 | 필수 여부 | 검증 |
| --- | --- | --- |
| 양력/음력 | 필수 | 기본값 양력, 명시적 선택 가능 |
| 출생 연·월·일 | 필수 | 실제 존재하는 날짜, 지원 범위, 미래 날짜 거부 |
| 윤달 여부 | 음력에만 사용 | 선택한 연월에 실제 윤달인지 확인; 양력 전환 시 상태 초기화 |
| 시간 상태 | 필수 | 정확한 시각 또는 모름 |
| 시·분 | 시각을 알 때 필수 | 24시간제, 00~23/00~59; 모름 선택 시 값 제거 |
| 출생국/시간대 안내 | 범위 확인 필수 | 초기 국내 출생 한정 문구·확인; 해외는 미지원 안내 |
| 상담 관심 주제 | 선택 | general/career/relationship 등 사전 정의 enum; 실제 주제 확정 후 고정 |
| 성인 체험 범위 확인 | 제품 정책 제안 | 초기 만 19세 이상으로 한정할지 운영자 결정; 법적 일괄 의무라고 표현하지 않음 |
| 개인정보 안내·AI 별도 선택 | 기능별 | B는 로컬 처리 안내, C는 실제 서버/외부 전송 안내와 필요한 동의 |

이름·주민번호·주소·전화·이메일을 기본 체험에 받지 않는다. 성별은 초기 범위에 대운 순역 등 해당 입력을 실제로 필요로 하는 기능을 넣지 않는 한 수집하지 않는다. 자유 질문 입력과 타인 궁합 입력은 후속 범위로 남긴다.

모바일은 입력 → 확인 → 결과의 짧은 흐름으로 만든다. 확인 단계에서 원래 양/음력 입력, 윤달, 시간/모름, 적용 기준을 확인할 수 있게 한다. 음력 날짜를 양력으로 변환했으면 원 입력과 변환 결과를 함께 설명한다.

### 3.2 내부 계산 결과

```ts
type SajuChart = {
  schemaVersion: string;
  engineVersion: string;
  calculationPolicyVersion: string;
  inputPrecision: 'minute' | 'unknown-time';
  pillars: {
    year: Pillar;
    month: Pillar;
    day: Pillar;
    hour: Pillar | null;
  };
  facts: ValidatedFact[];
  limitations: LimitationCode[];
};
```

`Pillar`의 간·지, `ValidatedFact`의 factId·근거·계산 규칙은 엔진 선정 후 명세화한다. 입력 정규화 정보는 표시와 서버 재계산에 필요한 범위에서 메모리로만 관리한다. 알 수 없는 시각을 숨겨 완전한 사주팔자처럼 반환하지 않는다.

초기 오행 표시는 포함 범위를 명확히 정한다. 예를 들어 천간·지지 표면 기준 집계와 지장간 가중 계산은 다르다. 집계 정책을 명시하지 않은 “오행 32%”·정밀 점수·성공 확률은 표시하지 않는다. 검증되지 않은 십성·신강약·용신 계산도 자동으로 확장하지 않는다.

### 3.3 기본 결과 화면

1. 입력 요약과 적용된 계산 기준, 수정 버튼.
2. 읽기 쉬운 연·월·일·시주 표; 한자에 한글 읽기와 설명을 제공.
3. 계산으로 확인한 제한된 특징과 학소 검수 원고에 따른 기본 풀이 3~5개.
4. 시간 미상·지원 범위·계산 기준 차이에 따른 제한 안내.
5. 초기에는 AI 설명·유료 전환 버튼을 표시하지 않는다. 후속 C를 별도 구현할 때만 상품·전송 안내와 함께 설계한다.
6. 이메일 상담 범위 안내와 CTA. 이메일 공란일 때는 준비 중 안내로 연결한다.

고정 풀이는 `조건 → 근거 factId → 검수 원고`로 관리한다. 같은 입력·정책이면 같은 기본 풀이가 나온다. 규칙이 없는 조합은 임의로 해석하지 않고 확인 가능한 정보와 일반적인 상담 준비 안내를 제공한다. 학소가 검수하기 전의 원고는 예시로만 표시한다.

사주 풀이는 전통적 해석을 참고하는 서비스임을 알린다. 사망·질병·사고·파산·이혼 확정, 투자 종목·매매 지시, 치료/약 중단, 공포를 이용한 고액 결제 유도는 결과와 CTA에 넣지 않는다. 현실의 중요한 판단을 대신하는 확정 예측으로 표현하지 않는다.

## 4. 유료 AI 기능의 후속 설계 — 현재 구현 범위 아님

이 절과 5절의 구현·실비 테스트는 별도 착수 요청 전에는 실행하지 않는다. 아래 설명 API는 유료 상품 전체 시스템 중 생성 계층의 초안일 뿐이다. 향후에는 결제 검증·주문 상태·접근 권한·생성/전달 실패·재전달·환불 설계가 선행되어야 하며, 이 API만 공개해 유료 서비스가 완성됐다고 판단하지 않는다.

### 4.1 AI의 허용 역할

AI는 서버에서 검증된 명식·사실·검수된 기본 풀이를 쉬운 한국어로 설명한다. 명식 재계산, 알려지지 않은 시주 생성, 운영자가 정하지 않은 학파 적용, 학소 경력·상담 후기 창작을 맡기지 않는다. 초기에는 자유 대화·웹 검색·도구 실행·외부 URL 조회가 없다.

입력 전 “계산된 사주 정보를 바탕으로 AI가 설명을 생성합니다”라고 안내하고 결과에도 AI 생성 표시를 둔다. 실제 사람이 검수하지 않은 결과에 “학소 선생님 검수 완료”를 붙이지 않는다. 생성형 AI 서비스의 사전 고지·결과 표시 관련 현행 규정과 적용 범위를 공개 전 확인한다. [인공지능기본법 제31조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1031810729)

### 4.2 AI 공급자 선정

특정 모델을 지금 고정하지 않는다. 한국어 설명 품질, 구조화 출력, 지연, 최대 비용, 입력/출력 보유, 학습 사용 여부, 처리 국가·하위 처리자, 삭제 조건, 상업 이용 조건을 공식 문서와 실제 API로 비교한다. API 계약과 일반 소비자용 챗봇 계정의 조건을 동일하게 가정하지 않는다.

공급자는 `provider.ts` 어댑터 하나를 통해 호출한다. 브라우저가 공급자·모델·프롬프트·출력 토큰 수·요금 옵션을 지정하지 못하게 한다. 공급자 장애 시 다른 회사로 몰래 전환하지 않는다. 전송 대상 변경은 정책·고지·계약 확인 후 반영한다.

### 4.3 공급자에 전송할 최소 데이터

- 허용: 검증된 간지와 factId, 시간 미상 등 제한, 선택 주제 enum, 검수된 설명 규칙.
- 기본 제외: 이름·연락처·상세 주소·출생 원문 날짜/시각·IP·쿠키·기기 식별자.
- Worker는 원본 출생 입력을 서버 계산 때문에 받지만 AI 공급자에는 전달하지 않는 구조를 기본안으로 한다.
- 명식 등 파생정보도 재식별 가능성이 있으므로 “완전한 익명정보”라고 단정하지 않는다. 전송·보유·이전 검토에 포함한다.

### 4.4 API 초안

`POST /api/v1/saju/interpret` · JSON만 허용 · 요청 본문 상한 기본 8KiB.

```json
{
  "schemaVersion": "1",
  "requestId": "클라이언트가 만든 무작위 UUID",
  "birth": {
    "calendar": "solar",
    "date": "1995-05-20",
    "isLeapMonth": false,
    "timeStatus": "known",
    "time": "14:30",
    "birthRegion": "KR"
  },
  "topic": "general",
  "noticeVersion": "구현 시 확정할 버전",
  "consent": { "aiProcessing": true },
  "turnstileToken": "실제 발급 토큰"
}
```

날짜는 계약 설명을 위한 가상 예시이며, 기대 명식 사례가 아니다. 필드·enum은 정책 확정 후 고정한다. 시간 모름이면 `time=null`, 음력 평달/윤달의 유효성은 서버에서 다시 검사한다. 알려지지 않은 필드는 거부한다.

API 처리 순서는 다음 원칙을 따른다.

1. HTTPS·method·content type·본문 크기·허용 Origin·Fetch Metadata 점검. CORS 허용만으로 남용을 막았다고 판단하지 않는다.
2. 입력 스키마, 현재 고지 버전, 해당 기능 동의, 지원 범위를 검증한다.
3. 익명 세션과 단기 중복 상태를 확인한다. 세션에 묶인 `requestId`를 사용하고 동일 ID의 다른 입력 재사용을 거부한다.
4. Turnstile 토큰을 서버에서 검증하고 실제 hostname/action을 확인한다. 클라이언트 위젯 성공만 믿지 않는다. 토큰은 단회성이므로 새 유료 시도에는 새 토큰을 사용한다. [공식 검증 안내](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)
5. 서버에서 계산하고 설명 가능한 사실만 구성한다. 브라우저가 보낸 명식·풀이·프롬프트를 신뢰하지 않는다.
6. 단기 호출 제한·동시성·일/월 예산을 원자적으로 예약한다. 동일 요청의 동시 실행은 한 번만 외부로 나간다.
7. 고정 공급자에 제한된 입력·최대 출력으로 한 번 호출한다. 타임아웃은 기본 30초 제안이며 실제 측정으로 조정한다.
8. 구조화 결과 스키마·길이·근거 factId·금지 내용·알 수 없는 정보 추가 여부를 점검한다. 원문 HTML을 렌더링하지 않는다.
9. 사용량 메타데이터를 정산하고 결과를 반환한다. 응답과 오류에 `Cache-Control: no-store`를 적용하고 CDN 저장 규칙에서도 제외한다.

오류나 브라우저 연결 끊김이 공급자 과금을 취소한다고 가정하지 않는다. 외부 호출 후 응답을 잃은 경우 자동으로 다시 호출하지 않는다. 중복 상태는 짧게 보관하되 결과 본문을 저장하지 않는 기본안이므로, 이미 처리한 요청을 재전송하면 새 결과 대신 중복 안내를 반환한다. 이 제약을 UX에 반영한다.

### 4.5 결과 계약

```ts
type AiExplanation = {
  schemaVersion: '1';
  requestId: string;
  source: 'ai';
  chartVersion: string;
  calculationPolicyVersion: string;
  promptVersion: string;
  sections: Array<{
    kind: 'summary' | 'strengths' | 'reflection' | 'preparation';
    text: string;
    evidenceFactIds: string[];
  }>;
  limitations: string[];
};
```

공급자 원응답을 그대로 노출하지 않는다. 내부 검증 후 서버가 `requestId`·버전·`source`를 부여한다. 분량은 처음 4개 영역, 한국어 총 800~1,200자 정도를 목표로 테스트한다. 글자수는 UX 목표이며 토큰 예산은 공급자 기준으로 별도 제한한다. 참조 factId의 존재와 사실 일치를 검사하고, 명식과 모순되면 폐기한다.

출력 점검만으로 모든 문제를 보장할 수 없으므로 실제 모델 평가와 공개 후 점검을 병행한다. 검증 실패 시 유료 재생성을 반복하지 않고 이미 계산한 기본 풀이와 문의 경로를 제공한다. AI 실패를 성공 통계로 계산하지 않는다.

## 5. 후속 AI 호출·비용 통제 계획

서버의 외부 AI 호출은 방문자 수만큼 비용이 생길 수 있다. “정적 호스팅이라 AI도 무료”라고 설명하지 않는다. Workers·저장소·AI·도메인·메시지 서비스 비용을 각각 구분한다. 무료 할당량과 가격은 실제 착수·공개 시점에 다시 확인한다. [Workers Static Assets 요금·제한](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)

| 통제 | 기본 제안 | 공개 전 확정 |
| --- | --- | --- |
| AI 전체 스위치 | 기본 off | 테스트·운영 값을 분리 |
| 입력/출력 | enum·고정 사실만, 최대 출력 제한 | 실제 토큰 분포 |
| 세션 제한 | 세션당 하루 3회 예시 | 공유기·쿠키 초기화 한계 안내 |
| 네트워크 제한 | 단기 HMAC IP 키 기반 보조 제한 | 보유 기간·공유망 영향·IPv6 우회 |
| 전역 제한 | 동시 3건·일 100건 예시 | 실제 운영 예산에 맞춘 값 |
| 일/월 예산 | 유료 호출 전에 최대 비용을 예약 | 운영자 승인 예산·통화·가격 버전 |
| 재시도 | 외부 유료 호출 자동 반복 없음 | 공급자 idempotency 실제 지원 여부 |
| 알림 | 예산 70/90/100% 등 제안 | 받을 계정·관측 방법 |

이 수치는 시작 제안일 뿐 실제 지출 승인이나 공급자 요금이 아니다. 쿠키·IP 제한은 사람 한 명당 보장된 제한이 아니므로 전역 비용 차단을 함께 둔다.

예산 검사는 단순 메모리 카운터나 정합성이 느린 캐시만으로 구현하지 않는다. Durable Object 등으로 같은 예산에 대한 동시 예약을 직렬화한다. 저장소 장애·가격 설정 누락·모델 미확정이면 새 AI 호출을 차단한다. 호출이 공급자에 도달했는지 불명확하면 예약액을 임의로 환급하지 않는다.

비용은 공급자의 단가표에 맞춰 계산한다.

```text
1회 상한 비용 = 최대 입력 토큰 × 입력 단가
             + 최대 출력 토큰 × 출력 단가
             + 사용 모델의 추가 과금 항목

월 예상 비용 = 예상 유료 호출 수 × 실측 평균 비용
            + Worker/제한 저장소/기타 운영 비용
```

예산은 정수 최소 통화 단위로 기록하고 KST 일/월 경계를 명시한다. 가격 버전 변경 시 상한을 재계산한다. 서비스 차단선은 자체 AI 지출의 보수적 상한이며, 공급자 청구 지연·환율·세금·다른 인프라 비용까지 완벽히 차단하는 보장으로 홍보하지 않는다. 공급자 측 지출 한도도 가능한 범위에서 병행한다.

## 6. 개인정보·보안·고지

### 6.1 데이터 흐름과 보유 기본안

“저장하지 않는다”는 앱의 저장 정책과 공급자·Cloudflare 등 실제 인프라 보유 범위를 구분해 쓴다. 로그·관측·백업·오류 보고 서비스까지 점검한 뒤 정책을 공개한다. 명식과 출생일을 제거해도 요청 메타데이터가 개인정보에 해당할 수 있음을 고려한다.

이메일 상담 내용은 홈페이지 무료 체험과 별도 데이터 흐름이다. 사이트가 사주 정보를 저장하지 않는다고 해서 상담 메일함에도 정보가 남지 않는 것은 아니다. 이메일 주소와 실제 운영 조건을 받으면 계정 접근권한·인증·보유/삭제·답변 담당·불필요한 민감정보 기재 자제 안내를 정한다. 사용자가 원치 않은 사주 결과 전송이나 개발자의 테스트 이메일 발송은 하지 않는다.

수집·이용 목적, 항목, 기간, 거부 권리와 영향 등 실제 필요한 고지를 구성한다. 서비스 제공, 선택적 분석, AI 외부 처리/국외 이전, 마케팅 동의를 한 체크박스로 묶지 않는다. 선택 기능을 거부해도 홍보 페이지와 로컬 기본 체험은 이용 가능하게 한다. [개인정보 보호법 제15조](https://law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1029335375)

해외 AI뿐 아니라 해외 클라우드·분석·예약 도구도 실제 전송·보관 범위를 확인한다. 국외 이전에는 동의 외의 법적 근거도 있을 수 있으므로 무조건 한 방식만 정답이라고 가정하지 않는다. 적용 근거, 수탁/제공 구분, 국가·수령자·목적·기간 등을 실제 계약에 맞춰 검토하고 고지한다. 미확정이면 AI 공개를 보류한다. [국외 이전 근거](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1034515803), [동의 시 고지 항목](https://law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029332501)

이 문서는 구현 요구사항이며 법률 검토 완료 증명은 아니다. 유료 판매·내부 예약을 추가할 때 사업자 표시, 통신판매 해당 여부, 결제·청약철회/환불, 전자상거래 기록 보존 등 실제 판매 형태에 맞는 검토를 별도로 한다. 지금 단계에서 임의의 환불 규정이나 법정 보유기간을 만들어 공개하지 않는다.

### 6.2 필수 보안 기준

- AI 비밀 키·Turnstile secret·HMAC 키는 서버 secret에만 보관. `PUBLIC_*`·브라우저 번들·소스맵·Git·스크린샷에 노출하지 않는다.
- `.env*`, `.dev.vars*`, 인증 파일은 기본 제외하고 값 없는 예시 파일만 추적한다. 환경변수 설명에 실제 키를 넣지 않는다.
- Worker 응답·오류 로그·개발자 콘솔에 본문·출생 정보·프롬프트·AI 결과를 출력하지 않는다. 랜덤 요청 ID·오류 enum·지연·비용 집계로 진단한다.
- AI 요청은 POST로만, 개인 입력을 URL·referrer·분석·OG·공유·QR에 넣지 않는다. AI 응답은 브라우저와 CDN 모두 저장하지 않게 검증한다.
- HTML 삽입 대신 텍스트/안전한 구조화 렌더링. 외부 링크 프로토콜·대상 제한, CSP·HSTS·referrer·프레임 정책을 실제 구성에 맞춰 검수한다.
- 익명 제한 세션은 무작위 값의 `Secure`, `HttpOnly`, 적절한 `SameSite` 쿠키 등으로 구성하고 목적·기간을 고지한다. 광고 식별자와 공유하지 않는다.
- 관리자 기능이 생기면 비밀번호를 JS에 넣지 않는다. 인증·권한·감사·최소 접근을 별도 설계한다. 초기에는 관리자 페이지를 만들지 않는다.
- 공개 자산 전체에 비밀·개인정보·미검수 문구가 없는지 배포 전 확인한다. 이름만 바꾼 비공개 파일을 `public/`에 두지 않는다.

## 7. 검색·접근성·성능

- 사업 정보는 화면·푸터·구조화 데이터에서 동일하게 관리한다. `LocalBusiness`는 실제 주소 등 조건에 맞는 경우에만 적용하고, 온라인 전용이면 적합한 다른 스키마를 검토한다. 가짜 주소·임의 별점·자기 후기의 리치 결과를 만들지 않는다. [Google LocalBusiness 안내](https://developers.google.com/search/docs/appearance/structured-data/local-business)
- 공개 페이지는 정적 HTML에서 제목·본문·주 링크를 읽을 수 있게 한다. JS를 꺼도 소개·상담·연락 안내를 이용할 수 있고 체험에는 JS 필요 안내를 표시한다.
- sitemap은 공개·승인된 일반 페이지/글만 포함한다. 개인 결과·API·시안·초안은 제외한다. 실제 생성 파일 이름을 확인한 뒤 robots에 연결한다. [네이버 robots 안내](https://searchadvisor.naver.com/guide/seo-basic-robots), [사이트맵 제출](https://searchadvisor.naver.com/guide/request-feed)
- noindex/robots는 접근 제어가 아니다. 미공개 시안·자료는 인증 등으로 보호한다. 공개돼버린 개인정보를 robots 설정만으로 해결하지 않는다.
- 홈은 만세력·AI SDK를 로드하지 않는다. 이미지 크기 지정·반응형 이미지·폰트 제한·지도 링크 우선으로 첫 화면을 가볍게 한다.
- 목표는 공개 정적 페이지의 LCP 2.5초 이하, CLS 0.1 이하, INP 200ms 이하를 지향한다. 출시 전에는 재현 가능한 모바일 실험실 측정, 출시 후에는 충분한 실제 방문 데이터로 판단한다. 수치 목표와 실측을 구분한다.
- 입력 오류를 색만으로 표시하지 않고 레이블·설명·초점 이동을 제공한다. 결과 갱신은 보조기술에 알리고 한자 표를 읽는 순서를 점검한다.

## 8. 버전·업데이트 관리
