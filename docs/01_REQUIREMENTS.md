# 학소 철학관 요구사항·서비스 기획

버전: 1.3 · 2026-11-04 · 관련 문서: [기술 명세](02_TECHNICAL_SPEC.md), [실행 계획](03_IMPLEMENTATION_PLAN.md), [운영자 결정표](04_OWNER_CHECKLIST.md)

## 확정된 운영 범위 — 다른 제안보다 우선 적용

- GitHub 저장소: **[BrawlNote/hakso](https://github.com/BrawlNote/hakso) / Private**, 사용자 생성 및 Edge 접근 확인. 홈페이지 배포는 별도 미구현이다.

- 소재지: **서울 강북구 한천로 1167 3층**.
- 초기 상담 방식: **이메일 상담만**. 방문·전화·영상·메신저 상담 및 외부 예약 서비스는 초기 범위에서 제외한다.
- 대표 정보와 상담 이메일 주소: **공란 유지, 사용자 추후 제공**. 공개 화면에 빈 레이블·임시 이름·임시 이메일을 표시하지 않는다.
- 홈페이지 사주 기능: **무료 제공**. 이메일 상담 요금은 별도 미정이므로 무료라고 광고하지 않는다.
- 유료 AI 풀이: **후속 계획만 작성**. 초기 AI 실호출·유료 상품·결제·AI CTA는 구현하지 않는다.

## 1. 목적과 기획 원칙

사이트의 첫 목적은 방문자가 학소 철학관의 상담 방식과 신뢰할 만한 근거를 이해하고, 상담을 문의하게 만드는 것이다. 무료 사주 체험은 방문 계기와 상담 전 이해를 돕는 기능이다. 체험 이용만 늘고 상담 연결이 어려워지는 구성을 피한다.

핵심 방문자는 모바일 검색으로 철학관을 찾는 사람, 지인 소개로 상호를 검색하는 사람, 사주를 처음 접하는 사람이다. 지역·연령·상담 주제의 우선순위는 운영자 인터뷰로 좁힌다. 아직 특정 지역이나 연령대를 실제 고객층이라고 단정하지 않는다.

성공 지표는 이메일 작성 시작·주소 복사와 실제 이메일 접수·상담 완료 건수다. 무료 체험 완료율은 보조 지표다. 메일 작성 창을 연 것을 발송·상담 완료로 계산하지 않는다. 이메일 미제공 상태에는 무료 체험 이용과 상담 안내 열람만 관측한다.

| 항목 | 기본 제안 | 이유 |
| --- | --- | --- |
| 첫 방문 메시지 | 어떤 고민을 어떻게 함께 살피는지 설명 | 추상적 권위보다 상담 내용을 이해시키기 |
| 주 행동 버튼 | 상담 문의하기 | 실제 운영 채널로 연결 |
| 보조 행동 버튼 | 무료 사주 체험 | 사주 기능을 통한 진입 |
| 콘텐츠 관리 | Markdown + 중앙 사업 정보 파일 | AI 작업·버전 관리·복구 용이 |
| 사주 계산 | 검증 가능한 계산 엔진 | 생성형 AI의 숫자·간지 추측 방지 |
| AI 역할 | 후속 유료 풀이의 설명 보조 계획 | 현재 구현 범위에서 제외 |
| 초기 상담 방식 | 이메일 상담만 | 주소 제공 후 메일 작성 연결; 자체 접수 DB 없음 |
| 홈페이지 사주 요금 | 무료 | 이메일 상담의 요금은 추후 별도 확정 |

| Markdown 콘텐츠와 메타데이터 | 상담 안내·칼럼·공지에 초안, 발행일, 검수 상태 적용 |

Starlight의 문서형 사이드바와 게임 정보 화면은 학소 홍보 메인에 그대로 적용하지 않는다. **기본은 일반 Astro 페이지와 자체 레이아웃**이다. 칼럼이 크게 늘어났을 때 지식 문서 영역에 Starlight 도입 여부를 별도 판단한다. 초기에는 Tailwind·React·CMS를 필수로 추가하지 않는다.

BrawlNote 저장소 전체, 게임 이미지·상표·문구·분석 스냅샷·비밀 파일·운영 DB를 복사하지 않는다. 일부 일반 코드 재사용은 소유권·라이선스와 의존성을 확인한 파일만 대상으로 한다. 새 저장소·도메인·Cloudflare 리소스는 학소 명의로 분리한다.

## 3. 범위와 출시 정의

| 등급 | 포함 범위 | 출시 기준 |
| --- | --- | --- |
| A 필수 | 홈, 소개, 이메일 상담 안내, 소재지 안내, FAQ, 정책, 공통 SEO | 이메일 공란 상태는 상담 준비 중으로 표시; 실제 접수 개시는 주소 제공 후 검증 |
| B 필수 | 생년월일 입력, 양/음력·윤달·시간 모름, 검증된 명식, 제한된 기본 풀이, 상담 CTA | 기술 명세의 계산 정책·기준 사례 통과 |
| C 후속 계획만 | 유료 AI 풀이의 상품·비용·호출 제한·고지·결제 계획 | 초기 구현하지 않음; 별도 요청이 있을 때 착수 |
| D 보류 | 회원, 내부 예약 DB, 자동 문자, 결제, 유료 보고서, 궁합·작명·택일 계산, 실시간 채팅 | 별도 요구사항·운영 책임·비용 확정 |

사주·궁합·작명·택일 등이 학소의 실제 상담 항목이면 A의 안내에 넣을 수 있다. 안내 페이지를 만든 것과 온라인 자동 계산을 제공하는 것은 다르다. 실제 제공 여부를 확인하지 않은 서비스를 판매 문구에 넣지 않는다.

초기에는 이메일 상담만 제공하므로 방문 예약·전화·길찾기를 주요 CTA로 배치하지 않는다. 소재지는 소개/푸터에 표시할 수 있고, `/visit/` 페이지가 필요 없다면 최초부터 메뉴·URL·사이트맵에서 제외한다. 지도 핀·교통·주차 정보는 별도 확인 없이 추정하지 않는다. 실제 상담 항목이 확정되기 전에는 서비스별 상세 URL을 대량으로 생성하지 않는다.

`/saju/`에는 공통 설명과 입력 폼만 정적 HTML로 들어간다. 개인 결과는 같은 화면 안에서 메모리로 표시한다. 생년월일이나 결과가 담긴 공유 URL·영구 상세 페이지는 만들지 않는다. 결과를 새로고침하면 사라지는 정책을 입력 전 안내한다.

## 5. 홈 화면 구성

1. 헤더: 학소 로고/상호, 소개, 상담 안내, 무료 사주, 칼럼, 문의하기. 모바일은 메뉴와 주 CTA가 쉽게 보이게 한다.
2. 첫 화면: 학소 철학관, 무료 사주와 이메일 상담에 대한 짧은 설명, “무료 사주 체험”과 “이메일 상담 안내”. 이메일 미제공 시 준비 중임을 표시한다.
3. 어떤 상담인가: 진로·관계·삶의 방향 등 운영자가 실제 다루는 주제 3~5개. 카드마다 상담 안내 연결.
4. 학소 소개: 실제 상담자 사진, 철학, 확인된 경력의 요점. 경력 연수·방송·자격·후기 수를 창작하지 않는다.
5. 무료 체험 소개: 기본 풀이와 실제 상담의 범위, 계산 방식, 무료 여부를 투명하게 안내.
6. 상담 절차: 이메일 문의 → 운영자 접수 확인·진행/비용 안내 → 확정된 방식으로 이메일 답변. 접수·비용·답변 기한은 나중에 제공받은 정책에 맞춘다.
7. 실제 이용 근거: 동의받은 후기 또는 학소의 상담 원칙. 후기가 없으면 원칙을 보여준다.
8. 소재지/상담 방법: 제공된 주소와 “초기 이메일 상담만 진행” 안내. 주소만으로 방문 상담이 가능하다고 쓰지 않는다.
9. FAQ 4~6개, 최신 공개 글 최대 3개, 운영 공지가 있을 때 공지 노출.
10. 하단 문의 영역과 푸터: 상호, 검증된 운영 정보, 정책 링크, 연락처. 미정 항목 숨김 규칙 적용.

모바일 하단 고정 CTA는 “무료 사주 보기”와 “이메일 상담 안내”를 기본으로 한다. 이메일 주소 제공 전에는 후자를 준비 중 안내 페이지로 연결하고 `mailto:`를 만들지 않는다. 주소 제공 후에만 “이메일 상담 문의”로 변경한다. 전화·예약 버튼은 넣지 않는다. iOS 안전 영역과 키보드가 입력 폼·동의란·결과를 가리지 않게 한다.

## 6. 디자인 방향

기본 제안은 따뜻한 종이색 바탕, 먹색 본문, 짙은 녹색 또는 남색 강조, 절제된 전통 인상이다. 색상·로고는 실제 자료를 확인한 뒤 확정한다. 모든 텍스트가 금색이거나 작은 한자만으로 표현되는 방식은 피한다.

- 제목은 한글 명조 계열을 제한적으로, 본문은 읽기 쉬운 고딕 계열을 사용한다. 폰트 라이선스를 기록하고 가능하면 서브셋·자체 호스팅한다.
- 본문 기본 크기는 모바일 16px 이상, 설명 문구도 확대해 읽을 수 있게 한다. 일반 텍스트 명도 대비는 4.5:1을 목표로 한다.
- 버튼은 터치 영역 44×44px 이상을 목표로 하고 키보드 포커스·오류 상태를 제공한다.
- 실제 공간·상담자 사진을 우선 사용한다. AI 이미지를 실제 학소 내부·상담자 모습으로 오인하게 쓰지 않는다.
- 디자인 시안은 모바일 홈, 데스크톱 홈, 사주 입력/결과, 상담 문의 화면을 먼저 만든다.
- 다크 모드는 초기 필수 범위에서 제외한다. 한 테마의 가독성과 신뢰감을 먼저 검수한다.

### 검색 유입 → 상담 문의

지역 검색/상호 검색 → 홈/이메일 상담 안내 → 실제 진행 방법 확인 → 이메일 주소 제공 후 메일 작성 → 운영자가 접수·진행 안내한다. 메일 작성 창을 열거나 주소를 복사한 것을 발송·접수·완료로 집계하지 않는다. 이메일 주소가 비어 있으면 “이메일 상담 준비 중”으로 안내하고 접수 기능은 노출하지 않는다.

### 무료 체험 → 상담 문의

체험 설명 → 입력·정책 안내 → 입력 확인 → 계산 → 무료 기본 결과 → 이메일 상담 안내. 초기 흐름에는 AI 설명·유료 전환이 없다. 이메일에 생년월일·명식·결과를 자동 첨부하지 않는다. 연락처는 무료 사주 이용의 대가로 필수 수집하지 않는다.

### 시간이 없거나 지원되지 않는 출생 정보

모름/지원 밖 상태를 명시 → 계산 가능한 항목만 제시하거나 계산 중단 → 실제 상담 문의. “정확한 출생 시간을 모르면 나쁜 사주” 같은 불안 유도 문구를 쓰지 않는다.

## 8. 콘텐츠 준비와 발행

| 자료 | 최소 필요 내용 | 공개 조건 |
| --- | --- | --- |
| 사업 기본 정보 | 상호, 연락 채널, 상담 방식, 응대시간, 실제 주소 여부 | 운영자 사실 확인 |
| 상담자 소개 | 공개 호칭, 소개, 철학, 검증 가능한 경력, 공개 사진 | 당사자 사용 허락 |
| 상담 상품 | 실제 항목·시간·가격/문의 방식·인원·추가비용·취소 조건 | 운영자 확정 |
| 공간 사진 | 외관, 입구, 내부, 대중교통/주차 안내 | 권리와 실제 장소 확인 |
| 로고·폰트 | 원본·색상·사용권 | 라이선스 기록 |
| FAQ | 실제 질문과 운영자 답변 | 운영 방식과 일치 |
| 후기 | 원문, 게시 허락, 익명화 기준 | 검증·동의가 있는 후기만 |
| 칼럼 | 주제·본문·근거/검수·상담 연결 | 초안 제외, 운영자 검수 |

초기 칼럼 제안은 4~6개다: “상담 전 준비할 정보”, “출생 시간을 모를 때”, “양력·음력·윤달의 차이”, “무료 자동 풀이와 개별 상담의 차이”, “진로 고민을 상담에서 정리하는 방법”, “이메일 상담 진행 안내”. 이는 제목 제안이며 작성·공개된 글이 아니다. AI 초안은 운영자가 검수한 뒤 발행한다.

글 메타데이터는 `title`, `description`, `publishedAt`, `updatedAt`, `draft`, `reviewStatus`, `author`, `reviewer`, `category`, `cover`, `coverAlt`를 기준으로 한다. 날짜는 실제 발행/수정 날짜를 쓴다. `draft=false`이고 `reviewStatus=approved`인 글만 공개한다. 검수자 이름은 실제 검수 때만 넣는다.

## 9. 홍보와 성과 측정

1. 상호·제공된 소재지·추후 제공될 이메일 표기를 일치시킨다. 네이버 플레이스 등 지역 사업자 채널은 이메일 상담만 제공하는 현재 형태의 적격성을 먼저 확인하고, 실제 방문 상담 가능으로 오인하게 등록하지 않는다.
2. Google Search Console·네이버 서치어드바이저에 소유 확인 후 실제 사이트맵을 제출한다. 제출 완료와 검색 노출을 구분한다.
3. 지역명이 확정되면 제목/설명에 자연스럽게 반영한다. 실제 영업 근거가 없는 지역별 복제 페이지를 만들지 않는다.
4. 초기 상담 채널은 이메일 하나로 통일한다. 주소 제공 후 메일 앱 연결과 주소 복사 대안을 검수한다. 전화·카카오·네이버 예약은 추후 범위 변경 전까지 추가하지 않는다.
5. QR은 일반 홈페이지나 상담 안내 URL만 담는다. 개인 사주 결과를 QR에 넣지 않는다.
6. 오픈 후 4주 동안 유입→체험→문의 클릭과 실제 문의·상담 완료를 함께 확인한다. 작은 표본에서 효과를 단정하지 않는다.

| 이벤트 | 허용 속성 | 해석 |
| --- | --- | --- |
| `consultation_click` | 정규화된 페이지·버튼 위치·채널 enum | 문의 의도 행동 |
| `email_compose_open` / `email_address_copy` | 버튼 위치만 | 메일 작성 시작/주소 복사; 실제 발송이나 접수 아님 |
| `saju_start` / `saju_complete` | UI 버전·기본/AI 구분 | 체험 진입/완료; 개인 입력 없음 |
| `saju_error` | 사전 정의 오류 코드만 | UI/API 품질 점검 |
| `article_consultation_click` | 공개 글 slug·버튼 위치 | 글의 문의 기여 |

초기 분석은 최소한으로 구성한다. 선택적 분석 도구를 넣는 경우 거부해도 사이트·체험이 동작해야 한다. 생년월일·명식·상담 내용·입력값·전체 쿼리·개인 결과·원문 오류는 분석 서비스로 보내지 않는다. 사주 폼/결과의 세션 녹화·자동 폼 수집·DOM 수집은 비활성화한다.

## 10. 운영자 확인이 필요한 출시 조건

미정이어도 와이어프레임·디자인·공통 컴포넌트·테스트 환경은 진행한다. 다음 항목은 해당 기능 공개 전에 확정해야 한다.

- A 공개 전: 확인된 정보·사진 권리·공개 정책·대표 URL과 이메일 공란 분기. 대표/이메일 미제공 상태에는 안내·무료 체험 공개와 실제 상담 접수 개시를 구분한다.
- B 공개 전: 계산 정책, 지원 출생 범위, 명식 기준 사례, 고정 풀이 원고 검수, 결과 안내.
- C 후속 착수 전: 별도 구현 요청과 상품·가격 결정 기준·결제/주문·전달/환불 설계. 후속 공개 전 공급자·계약/외부 처리·고지·예산·실제 호출까지 검수한다.
- D 착수 전: 내부 예약/결제/회원의 필요성, 데이터 보관·접근권한·취소/환불·운영 책임.

### 이메일 상담의 공란 처리와 추후 개시

대표 정보와 상담 이메일은 사용자가 나중에 제공하기로 했다. 반복해서 입력을 요구하지 말고 공란으로 개발한다. 이메일 미제공 상태에서는 상담 준비 중 안내만 제공하고 빈 링크·가짜 수신 주소·접수 폼·자동 발송 기능을 만들지 않는다. 사주 무료 체험과 홍보 페이지 구현은 계속 진행할 수 있다.

실제 이메일을 받으면 중앙 사업 정보에 반영하고 메일 작성 연결·주소 복사·오탈자·모바일 동작을 검수한다. 제목에 일반 상담 문의 문구를 넣을 수 있으나 출생 정보·사주 결과·연락처를 URL의 본문에 자동 삽입하지 않는다. 상담 항목·비용·답변 기한·수집 항목·보유/삭제 기준은 실제 운영자가 정한 뒤 안내한다.

## 11. 유료 AI 풀이 후속 기획 — 현재 구현 금지

| 항목 | 후속 계획 |
| --- | --- |
| 상품 후보 | 무료 기본 풀이를 유지하고 선택형 상세 AI 보고서를 별도 제공하는 안 |
| 결제 모델 | 최초 후보는 1회 결제형; 구독/자동 갱신은 별도 수요 확인 후 검토 |
| 차별점 | 단순 글자수 증가보다 검증된 계산 근거·주제별 설명·한계·상담 준비 정리 |
| 품질 기준 | 학소 원고/문체 검수, 명식 모순 없음, 시간 미상 제한, AI 표시 |
| 가격 결정 | 실제 토큰·인프라·결제 수수료·고객지원·재처리 비용 측정 후 결정; 현재 금액 미정 |
| 전체 흐름 | 상품·범위 안내 → 결제 확인 → 생성 → 전달 → 실패/환불·문의 처리 |
| 주요 기술 과제 | 결제 서버 검증·웹훅·중복 생성/청구 방지·결제 후 실패·재전달·접근 통제 |
| 개인정보 과제 | 결과 전달/재열람에 필요한 보유 여부·기간·삭제·외부 처리 계약 확정 |

| 착수 조건 | 사용자의 별도 구현 요청 + 상품/공급자/예산/판매·정책 조건 확정 |

무료 사주 화면에 선결제·잠금 해제·결제 유도·출시 예정일을 임의로 노출하지 않는다. 유료 AI 기획을 남긴 것을 출시 약속이나 실제 판매 개시로 취급하지 않는다.
