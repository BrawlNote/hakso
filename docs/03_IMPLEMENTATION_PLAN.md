## 2. 착수 점검과 macOS 개발 환경

### 2.1 맥에서 먼저 확인할 것

- 실제 작업 폴더, 기존 Git 여부, branch/remote, 수정·미추적 파일을 확인한다.
- 맥의 `AGENTS.md`, `GEMINI.md`, 해당 프로젝트 규칙이 있으면 읽는다. BrawlNote 규칙을 학소 전체에 무작정 복사하지 않는다.
- `README.md`와 본 패키지를 읽고 확인한 내용·추정·미정을 구분한다.
- Mac 모델/CPU, macOS, `node -v`, `npm -v`, `git --version`, Safari 버전을 시험 기록에 남긴다. 사용자 홈 이름이나 다른 개인정보는 필요 이상 기록하지 않는다.
- 저장소가 비어 있지 않으면 생성기로 덮어쓰지 않는다. 필요하면 별도 임시 위치에서 골격을 만든 뒤 충돌 없는 파일만 반영한다.
- BrawlNote 참고 저장소가 맥에 없다면 이 기획을 기준으로 진행한다. 비교가 필요하면 원본 전체 대신 필요한 소스만 확보한다. Windows의 `.env`·쿠키·`node_modules`·대용량 스냅샷은 옮기지 않는다.

맥 작업 위치 예시는 `~/Projects/hakso`이며 실제 위치는 확인 후 정한다. 저장소가 이미 준비된 이후의 명령 예시는 다음과 같다.

```bash
cd "$HOME/Projects/hakso"
pwd
git status --short
git remote -v
```

Node 버전을 정하고 `.nvmrc`·npm 버전·lockfile을 만든 뒤 재현 설치한다. 다음은 **nvm을 이미 사용하는 맥**의 예시다. nvm이 없으면 사용자의 기존 버전 관리 도구를 존중하고 공식 설치 절차로 준비한다.

```bash
nvm install
nvm use
node -v
npm -v
npm ci
npm run dev
```

`npm ci`는 유효한 `package-lock.json`을 만든 뒤 사용한다. 최초 패키지 구성은 선택한 버전으로 설치해 lockfile을 생성한다. 맥에서는 `npm.cmd`나 PowerShell의 `Set-Location`을 사용하지 않는다. Windows 경로, `.exe`, 드라이브 문자, 대소문자 불일치가 코드에 들어가지 않게 한다.

### 2.2 구현해야 할 명령 계약

다음 명령은 **지금 존재하는 명령이 아니라 구현 시 만들 계약**이다. AI 관련 명령과 서버 코드·리소스는 후속 C 착수 때 추가하며 초기 A+B에 미리 만들지 않는다.

| 명령 | 역할 |
| --- | --- |
| `npm run dev` | Astro 개발 서버; 기본 체험은 AI 키 없이 사용 |
| `npm run check` | Astro/TypeScript 검사 |
| `npm run build` | 승인 콘텐츠만 담은 프로덕션 정적 출력 |
| `npm run preview` | 정적 빌드 미리보기; Worker API 검증과 구분 |
| `npm test` | 전체 단위·계약 테스트; 실비 API 기본 제외 |
| `npm run test:saju` | 역법·계산 정책·고정 풀이·범위 테스트 |
| `npm run test:content` | 사업 정보·초안 제외·링크·메타데이터 검증 |
| `npm run test:e2e` | 브라우저 핵심 흐름; 합성 데이터 사용 |
| `npm run test:ai` | 후속 C 착수 때 추가; 현재 구현 대상 아님 |
| `npm run test:security` | 공개 출력의 비밀/개인정보·캐시·헤더 등 명시한 검사 |
| `npm run cf:dev` | 빌드된 자산 + 로컬 Worker 런타임 통합 |
| `npm run deploy:preview` | 확인된 미리보기 리소스만 배포 |

실비 테스트는 별도 옵션/명령으로 분리하고 기본 CI에서 실행하지 않는다. `.env.example`과 서버 secret 설정 예시에는 변수명·역할·필수 단계만 쓴다. 배포 스크립트의 기본 대상이 운영이 되지 않게 한다.

## 3. 사주 검증 계획

명식의 기대값은 채택 엔진의 반환값을 그대로 저장해서 만들지 않는다. 한국천문연구원 등 달력 기준 자료, 적법하게 확보한 독립 자료, 학소가 확정한 명리 기준을 역할별로 대조한다. 공개 테스트 사례는 합성 입력으로 구성하고 각 기대값에 출처·정책·확인자를 남긴다.

최소 **50개 이상의 서로 다른 사례**를 준비하되 숫자보다 아래 위험 구간의 실제 커버리지가 우선이다. 기대값을 확보하지 못한 경계는 “검증 완료”가 아니라 미지원 또는 미완료로 남긴다.

| 범주 | 반드시 포함할 사례 |
| --- | --- |
| 일반 날짜 | 서로 다른 연·월·일·시간, 양력과 동치 음력 입력 비교 |
| 윤년 | 정상 2월 29일·평년 2월 29일·월말·연말 |
| 음력 | 평달·실제 윤달·존재하지 않는 윤달·29/30일 유효성 |
| 연주 | 선택한 연도들의 입춘 직전/정각/직후 |
| 월주 | 복수 월의 절입 직전/정각/직후; 음력 월 경계와 구분 |
| 일/시주 | 정책에 따른 22:59/23:00/23:59/00:00/00:01, 여러 시진 경계 |
| 시간 미상 | 시주 null·관련 해석 없음·수정 시 이전 시간 값 제거 |
| 시간대 | 한국 과거 오프셋·DST 중 지원 사례, 미지원·중복/누락 시각 처리 |
| 실행 환경 | 브라우저/Node/Worker 동일, 실행 기기 시간대가 달라도 동일 |
| 입력 상태 | 양력↔음력, 윤달 토글, 시간 알음↔모름 변경 후 상태 정합 |
| 지원 범위 | 최소/최대 지원일 직전·해당일·직후, 미래 입력·해외 출생 |
| 표시 | 한자/한글 대응·결과 제한 안내·원 입력과 변환 결과 |

달력 변환 사례만 50개 통과한 것을 연·월·일·시주 전체 검증으로 보고하지 않는다. 시간 미상의 세 기둥은 검증된 정책에 따라 계산하되 경계 모호성이 남으면 그 제한을 표시한다.

엔진 업데이트 시 기준 사례 전체를 다시 실행한다. B와 C의 서버 재계산은 같은 계산 정책으로 같은 결과가 나오는 계약 테스트를 둔다. 대운·궁합 등 범위를 늘리면 별도 정책·테스트를 추가하고 기존 시험을 대신 사용하지 않는다.

## 4. 후속 유료 AI 검증 계획 — 이번에는 실행하지 않음

### 4.1 모의 API로 검증할 것

- AI off, 키 없음, 고지 구버전, 동의 없음, 잘못된 필드·날짜·시간, 해외 출생, 경계 모호성.
- Origin/action/hostname 불일치, Turnstile 누락·만료·재사용·외부 검증 장애.
- 공급자 429/5xx/timeout, 잘못된 JSON, 너무 긴 결과, 없는 factId, 새로운 시주·간지 창작.
- HTML/XSS 문자열, 공포 유도·질병 확정·투자 지시·허구 경력 등 부적절 출력.
- 동일 ID 동시 제출, 같은 ID 다른 입력, 브라우저 중단 후 재전송, 토큰 재사용.
- 동시 요청에서 일/월 예산·횟수·동시성 상한 초과 방지, 제한 저장소 장애 시 차단.
- KST 일/월 경계, 가격 버전 변경, 실제 사용량 누락, 과금 여부 불명확 상태.
- 응답/로그/분석/저장소에 원문 출생 정보·결과가 남지 않는지 검증.
- AI 차단·장애가 홈·문의·기본 계산을 막지 않는지 확인.

### 4.2 실제 공급자로 검증할 것

공급자·예산이 확정되면 합성 사례로 최소 30개 평가 세트를 구성한다. 시간 미상·경계 제한·다양한 입력·주제별 설명을 포함하고 일부는 반복 호출해 변동을 평가한다. 실비 횟수와 상한을 먼저 정하고 기록한다.

평가 항목은 명식 사실 일치, 알 수 없는 정보 미창작, 한국어 가독성, 과장·확정 예언 없음, 운영자 문체 적합, 적정 길이, 오류 처리, 실제 지연·토큰·비용이다. 계산 사실 모순·개인정보 노출·중대한 부적절 출력은 공개 차단 사유다. 단순한 자연어 표현 차이는 별도 품질 개선으로 기록한다.

모의 응답만 통과하면 “API 모의 검증 완료”다. 실제 HTTP 성공·응답 스키마·출력 평가·사용량 증거가 있어야 “실제 AI 연결 검증 완료”로 보고한다. 공급자 전체 서비스 품질이나 모든 미래 출력의 안전을 보장한다고 쓰지 않는다.

## 5. 화면·콘텐츠·브라우저 검수

### 5.1 화면 환경

- 폭: 320, 390, 430, 768, **800**, 1024, 1440px.
- 브라우저: Chromium, WebKit 자동화 + 실제 macOS Safari. 접근 가능한 경우 실제 iPhone Safari·Android Chrome도 확인한다.
- 상태: 긴 제목·사진 없음·칼럼 없음·공지 있음/없음·이메일/대표 공란·가격 미확정·시간 모름·오류·키보드 표시. 긴 AI 결과 검수는 후속 C 때만 진행.
- 접근성: 키보드 탐색, 포커스 표시/이동, 레이블과 오류 설명, 결과 알림, 200% 확대, reduced motion, VoiceOver 핵심 흐름.
- JS off: 홈·소개·상담·연락 링크 정상, 체험에는 사용 조건 안내. AI/API 오류가 일반 페이지 표시를 막지 않음.

Playwright WebKit 통과를 실제 Safari/iPhone 테스트 완료라고 적지 않는다. 실제 기기가 없으면 미검증으로 기록하고 공개 위험을 판단한다. 맥 개발 환경 검수는 Windows 결과로 대신 완료 처리하지 않는다.

### 5.2 사실·콘텐츠 검수

- 실상호·주소·연락처·가격·영업시간·추가요금·변경/취소 조건을 운영자와 대조한다.
- `TBD`, `TODO`, 임시 전화번호, example URL, 가짜 후기, 검수되지 않은 경력·수상·방송 표현이 공개 빌드에 없는지 확인한다.
- 초안/미승인 콘텐츠가 목록·검색·사이트맵·관련 글·RSS 등 어디에도 유출되지 않는지 확인한다.
- 주요 CTA와 무료 체험·이메일 준비 중 안내를 모바일에서 확인한다. 실제 이메일 제공 후 메일 작성 연결·주소 복사를 검수한다. 지도 링크를 추가할 때는 소재지 표시를 먼저 확인한다. 테스트 이메일은 별도 요청 없이 보내지 않는다.
- 화면에 보이는 가격/시간과 구조화 데이터가 일치한다. 구조화 데이터에 없는 사실을 추가하지 않는다.
- 제공된 주소를 정확히 반영하고 초기 방문/전화 상담 가능 문구가 없는지 확인한다. 대표 정보·이메일 공란은 숨기고, 이메일 미제공 상태에서 빈 mailto·가짜 접수·AI/결제 CTA가 없는지 검증한다.
- 폰트·사진·로고·후기 권리를 기록한다. 허구 공간 사진과 실제 공간 사진이 혼동되지 않게 한다.

## 6. 완료 검수표

| 게이트 | 필수 증거 | 실패하면 |
| --- | --- | --- |
| G-A 홍보 | 실제 정보 검수, 이메일 공란 시 준비 중 분기, 반응형·정책·SEO·HTTP | 정보/무료 체험 공개와 실제 이메일 접수 개시를 구분; 접수는 주소 제공 후 검수 |
| G-B 사주 | 확정 계산 정책, 출처 있는 기준 사례, 경계/미상, 실제 브라우저 결과 | B를 비공개/예시로 유지; A 선공개 가능 |
| G-C 후속 유료 AI | 별도 착수 때 결제/주문·고지·예산·호출·전달·실패/환불 검증 | 현재 후속 계획만; 코드·실호출·판매 없음 |
| G-R 운영 | 운영 URL, Git SHA와 배포 대응, HTTPS·캐시·404·정책·채널 | 배포 완료로 보고하지 않음 |

코드가 없던 순수 문서 단계에는 빌드 통과를 주장하지 않는다. 기능 구현 후에는 변경 관련 시험부터 실행하고, 공개 전 전체 단위/계약·타입·빌드·콘텐츠·보안·핵심 E2E를 한 번 완결한다. 실패 원인이나 새 변경이 없으면 같은 전체 시험을 이유 없이 반복하지 않는다.

## 7. Git·미리보기·운영 배포

1. 학소 전용 저장소와 배포 대상을 확인한다. 기존 파일·타인의 변경을 보존한다.
2. 기능 단위 브랜치와 커밋을 사용하고 관련 파일만 stage한다. 비밀·개인 입력·테스트 결과 원문이 들어가지 않는지 diff를 확인한다.
3. CI에서 재현 설치·타입·테스트·빌드를 수행한다. 기본 CI에 실제 AI 결제 호출을 넣지 않는다.
4. 미리보기 URL에서 라우팅·정적 자산·Worker API·보안 헤더·캐시·모바일 화면을 확인한다.
5. 공개 정보·계산 기준·AI 계약/예산 등 해당 출시 조건이 충족되면 승인된 공개 범위로 운영 배포한다. 아직 공개 요청이 없다면 검토 가능한 미리보기와 변경 요약까지 준비한다.
6. 실제 도메인 HTTPS, 대표 호스트/canonical, robots·실제 sitemap, 허용된 API, 404, CTA를 다시 확인한다.
7. 원격 SHA·배포 버전·실제 운영 URL의 대응을 기록한다. 정적 페이지와 API가 서로 다른 버전이 아닌지 확인한다.
8. 마지막 정상 버전 복구 방법과 AI 즉시 중단 방법을 검증한다.

배포 전 테스트용 noindex가 운영 전체에 남지 않게 확인한다. 반대로 preview가 운영 canonical로 색인되거나 개인 테스트 데이터가 공개되지 않게 한다. 검색 도구 소유 확인·사이트맵 제출·검색 노출은 각각 별도 기록한다.

| 상태 | 근거 | 보고 문구 예시 |
| --- | --- | --- |
| 로컬 구현 | 실행 화면·테스트·빌드 | 로컬 구현/검수 완료 |
| 커밋 | 커밋 SHA | 로컬 커밋 완료 |
| 원격 전달 | 원격 브랜치 SHA 일치 | 원격 전달 확인 |
| 미리보기 | 배포 ID·URL·검수 | 미리보기 검수 완료 |
| 운영 배포 | 운영 배포 ID·버전 | 운영 배포 실행 확인 |
| 실제 공개 동작 | 운영 HTTP·화면·채널/API | 운영 사이트 검수 완료 |

## 8. 예상 작업량과 위험 관리

아래는 1인 개발, 자료를 제때 받고 단계별 검수를 진행하는 조건의 **계획용 작업일 추정**이다. 견적이나 완료 보장이 아니다. AI가 코드를 빨리 만들어도 운영자 자료·계산 대조·실제 기기·외부 계정 확인 시간은 별도로 필요하다.

| 구간 | 추정 작업일 | 주요 변수 |
| --- | --- | --- |
| A 홍보·기반·시안·내용·preview | 6~10일 | 사진/가격/연락 자료와 디자인 수정 |
| B 계산 비교·정책·기본 풀이·UI·검증 | 추가 7~12일 | 한국 역법·경계·원고 검수 |
| C 생성 계층·고지·제한·평가 | 후속 착수 시 참고 5~8일 | 유료 상품의 결제/주문·재전달·환불 구현 시간은 포함하지 않음 |
| 운영 공개·추가 기기 검수·인계 | 추가 2~4일 | DNS·계정·기기 접근 |

A+B는 약 15~26 작업일을 계획용 초안으로 잡는다. 이메일 주소 미제공 상태에는 준비 중 화면까지 구현하고 실제 접수 연결은 추후 진행한다. C는 현재 일정에서 제외한다. 유료 AI는 결제·주문·전달·고객지원까지 범위를 정한 뒤 별도로 다시 산정하며, 생성 API의 참고 작업량을 유료 서비스 전체 견적으로 사용하지 않는다.

| 위험 | 조기 대응 | 남길 결정 |
| --- | --- | --- |
| 실제 운영 정보 지연 | 시안의 예시/미정 표시, 공개 빌드 차단 | 어떤 정보가 누구 확인 대기인지 |
| 만세력 기준 불일치 | 07단계 비교 실험 선행, 지원 범위 축소 | 학소 기준·출처·제외 구간 |
| 후속 AI 품질·지연·비용 | 현재 C 구현 제외, 별도 요청 시 평가 | 후속 모델·예산·실측 평가 |
| 개인정보 고지 미완성 | 로컬 기본 계산 우선, AI 전송 공개 보류 | 실제 공급자·전송 경로 |
| 문의는 많으나 응대 불가 | 실제 응대시간·확정 절차 표시 | 주 채널·응대 담당 |
| 기능 범위 과다 | 회원·결제·자체 예약을 D로 분리 | 확장 착수 근거 |
| 특정 개발 도구 의존 | 문서·표준 Git/npm·분리 모듈 | 새 도구에서 재개할 절차 |

## 9. 운영 인계와 오픈 후 일정

공개 시 다음을 전달한다: 콘텐츠 수정법, 문의 채널 변경법, 계산 정책 변경 절차, secret 변경 위치, AI on/off와 예산 변경, 사용량 확인, 장애 대응, 롤백, 도메인·계정 소유 정보, 지원하지 않는 출생 범위, 미검증 기기/기능. 실제 비밀 값은 문서에 넣지 않는다.

- 공개 당일: HTTPS·중요 URL·연락 링크·실제 기능·배포 버전·AI 차단 스위치 확인.
- 1주차: 오류·비용·스팸·모바일 입력 이탈·문의 응대 확인. 개인정보가 있는 원문은 수집하지 않는다.
- 4주차: 유입→체험→문의 클릭과 실제 상담 집계 비교. 비용 대비 가치가 없으면 AI 축소/중단을 검토한다.
- 정기 점검: 휴무/가격/채널 변경 시 즉시 갱신, 월별 비용/계정·의존성·계산 원고 변경 검토.

후속 개발용 `docs/PROGRESS.md`에는 완료 단계, 수정 파일, 실행 시험, 미실행 항목과 이유, 미정 결정, 다음 첫 행동을 남긴다. “다 했음” 대신 재개 가능한 근거를 쓴다.
